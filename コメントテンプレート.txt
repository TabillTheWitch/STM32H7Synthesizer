1. PURPOSE — クラス・関数の存在理由
「なぜこのクラスが存在するのか」を一言で示す。
記載例
// PURPOSE: M4側DMAバッファをM7側で安全に参照するための抽象化。

2. WHY — 設計意図は何か（意図）
コードから読み取れない“理由”を書く。
記載例
// WHY: DCacheを先に有効化するとM4が共有RAMを読めなくなるため。

3. HOW - 実際にどう動くか（動作説明）
記載例
// HOW:
// ボタン押下イベントはディスパッチャから通知され、
// onUpButton / onDownButton / onLeftButton / onRightButton が呼び出される。

4. CONSTRAINT — 制約（リアルタイム・割り込み・ハード）
ハードウェア・RTOS・割り込みなどの制約を書く。
記載例
// CONSTRAINT: 割り込みコンテキストから呼ばれるため再入不可。ロック禁止。

5. ORDER — 初期化順序の理由
順序そのものではなく 順序の理由 を書く。
記載例
// ORDER: DMA開始前にFIFOをクリアしないとSAI FIFO underrunが発生する。

6. SCOPE — 責務の境界（何をしないか）
「このクラスは何を担当しないか」を明確にする。
記載例
// SCOPE: このクラスはバッファ管理のみ担当。DSP処理は行わない。

7. HISTORY — 歴史的経緯（設計資料に書けない情報）
設計の背景にある“過去の事情”を書く。
記載例
// HISTORY: HALの初期化順序バグによりDMAを先に初期化する必要がある。


| 種別           | 何を書く？ | 使う場面                    |
| ---            | ---        | ---                         |
| **PURPOSE**    | 存在理由   | 抽象化・設計意図            |
| **WHY**        | 理由       | ハードの癖・順序の意図      |
| **HOW**        | 動作説明   | 実際にどう動くか            |
| **CONSTRAINT** | 制約       | 割り込み・リアルタイム・DMA |
| **ORDER**      | 順序の理由 | 初期化順序が壊れやすい      |
| **SCOPE**      | 責務の境界 | 誤用防止                    |
| **HISTORY**    | 過去の事情 | バグ回避・設計の背景        |
